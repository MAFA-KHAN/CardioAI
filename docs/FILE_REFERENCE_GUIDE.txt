1.  phase_1.ipynb                                               [3.0 MB]
    THE BRAIN — Machine Learning Training Notebook
================================================================================

  What it is:
    Your first and largest Jupyter notebook. This is where the entire machine
    learning pipeline lives — from raw data to trained model file.

  What it does (in order):
    ① Loads the UCI Heart Disease Dataset (Cleveland, 303 patients)
    ② Performs Exploratory Data Analysis (histograms, correlation heatmaps,
       class balance checks, box plots per feature)
    ③ Handles missing values ('?' characters in original dataset)
    ④ Encodes categorical variables using one-hot encoding:
         cp (chest pain type) → 3 binary columns
         restecg              → 2 binary columns
         slope                → 2 binary columns
         thal                 → 2 binary columns
    ⑤ Engineers 4 new interaction features:
         age_risk_group, bp_chol_interaction,
         exercise_stress_score, thalch_age_ratio
    ⑥ Applies StandardScaler (fits ONLY on training data)
    ⑦ Trains THREE models for comparison:
         Model 1 (Baseline):     Logistic Regression
         Model 2 (Intermediate): Random Forest
         Model 3 (Advanced):     XGBoost ← SELECTED FOR PRODUCTION
    ⑧ Evaluates all models: Accuracy, Precision, Recall, Specificity,
       F1-Score, ROC Curve, AUC, Confusion Matrix
    ⑨ Analyzes bias-variance tradeoff and regularization effect
    ⑩ Applies K-Means clustering (unsupervised, k=3 clusters)
    ⑪ Exports the trained model and scaler:
         → heart_disease_model.pkl  (XGBoost model)
         → heart_scaler.pkl        (StandardScaler)

  Who uses it:
    You (academic submission). The .pkl files it generates are what server.py
    loads to run live predictions.

  Size: 3.0 MB — Large because it contains all output cells, plots,
  training logs, and the embedded model data inside the notebook.

3.  heart_disease_model.pkl                                    [117 KB]
    THE MODEL — Trained XGBoost Classifier (Binary File)
================================================================================

  What it is:
    A serialized (pickled) Python object containing the fully trained
    XGBoost classifier from phase_1.ipynb.

  What it stores:
    - All XGBoost tree structures (learned from 303 training patients)
    - Feature weights, split thresholds, leaf values
    - Model hyperparameters (n_estimators, max_depth, learning_rate, etc.)
    - L1 and L2 regularization parameters

  How it's used:
    server.py loads it on startup:
      model = joblib.load("heart_disease_model.pkl")
    Then uses it to predict:
      prob = model.predict_proba(scaled_data)[0][1]
      → Returns probability of heart disease (0.0 to 1.0)

  Critical note:
    This file MUST stay in the ml/ folder. If deleted or moved,
    server.py falls back to a simple DemoModel (basic sigmoid function)
    and predictions become approximations, not real XGBoost output.

  DO NOT EDIT this file manually — it is a binary format that will
  become corrupted if opened in a text editor.

4.  heart_scaler.pkl                                           [1.6 KB]
    THE NORMALIZER — Fitted StandardScaler (Binary File)
================================================================================

  What it is:
    A serialized Python StandardScaler object fitted on the training data
    in phase_1.ipynb. Tiny file — only stores 21 mean values and
    21 standard deviation values (one per feature).

  What it does:
    Transforms raw patient inputs:
      scaled_value = (raw_value - training_mean) / training_std
    This ensures new patient data is in the same statistical range
    the model was trained on.

  Why it matters:
    If you use a different scaler, or scale the data differently, the
    model receives out-of-distribution inputs and predictions become wrong.
    The scaler must EXACTLY match what was used during training.

  How it's used:
    server.py:  scaled = scaler.transform(patient_dataframe)
    This happens before EVERY prediction.

  Version note:
    Trained with scikit-learn 1.6.1, loaded in 1.7.2. A warning appears
    at server startup but the scaler works correctly — StandardScaler's
    core math (subtract mean, divide std) has not changed between versions.

5.  server.py                                                  [15 KB]
    THE API — Flask Backend Server
================================================================================

  What it is:
    A Python Flask web server that acts as the bridge between the
    browser frontend and the trained machine learning models.

  What it does:
    ① Loads heart_disease_model.pkl and heart_scaler.pkl on startup
    ② Exposes two HTTP endpoints:

    ENDPOINT 1: POST /predict
      Receives: JSON with 13 patient features from the browser
      Does:
        - build_feature_df()   → Creates 21-column feature DataFrame
                                  (mirrors phase_1.ipynb preprocessing exactly)
        - scaler.transform()   → Normalizes features
        - model.predict_proba()→ Gets disease probability from XGBoost
        - determine_risk()     → Classifies as High/Medium/Low Risk
        - build_medical_graph()→ Builds patient-specific decision graph
        - a_star_search()      → Finds optimal care pathway (from phase_2)
        - generate_initial_facts() → Creates symbolic facts from patient data
        - forward_chaining()   → Runs 20 KB rules (from phase_2)
        - generate_recommendations() → Generates clinical action items
      Returns: JSON with ML result, A* pathway, KB trace, recommendations

    ENDPOINT 2: POST /simulate
      Receives: Same patient JSON
      Does:
        - Runs base prediction first
        - Then runs 6 counterfactual "probe" predictions:
            "What if BP were 120?"
            "What if Cholesterol were 180?"
            "What if Max HR increased by 15?"
            "What if ST Depression were 0?"
            "What if Exercise Angina were removed?"
            "What if Thalassemia were normal?"
        - Each probe changes ONE value, reruns the full pipeline
        - Computes delta (probability change) for each
      Returns: JSON with base probability + sensitivity dictionary

  How to run it:
    python server.py
    → Starts on http://localhost:5000
    → Must be running for the Assessment and Simulator tabs to work

  Key functions ported from notebooks:
    build_feature_df()        ← from phase_1.ipynb preprocessing
    a_star_search()           ← from phase_2_(2).ipynb
    build_medical_graph()     ← from phase_2_(2).ipynb
    knowledge_base (R01–R20) ← from phase_2_(2).ipynb
    forward_chaining()        ← from phase_2_(2).ipynb
    generate_recommendations()← from phase_2_(2).ipynb

10. algorithms.js                                              [19 KB]
    THE AI ENGINE — A*, KB, and TF-IDF in JavaScript
================================================================================

  What it is:
    A pure JavaScript implementation of the AI algorithms from
    phase_2_(2).ipynb. Runs ENTIRELY IN THE BROWSER — no server needed.

  What it contains:

    A* SEARCH:
      aStarSearch(graph, start, goal, heuristic)
        → Min-heap priority queue using array + sort
        → Expands nodes in order of f = g + h
        → Returns optimal path array and total cost
      heuristicValues — distance estimates per node to "Goal State"
      buildMedicalGraph(riskState, params) — dynamic graph per patient

    KNOWLEDGE BASE (20 Rules):
      knowledgeBase — array of {id, if, then, source} objects
        R01 elderly_patient → age_related_cardiac_risk (AHA)
        R02 high_bp → hypertension (AHA/ACC)
        ... through R20 low_risk → preventive_education (WHO)
      generateInitialFacts(params) — converts numeric inputs to symbolic facts
      forwardChaining(facts, rules) — runs inference until saturation
        → Returns: [derivedFacts, inferenceTrace]

    TF-IDF MEDICAL SEARCH:
      medicalDocs — array of 15 clinical reference documents
        Each has: title + full clinical text
        Topics: hypertension, cholesterol, thalassemia, chest pain,
                ECG, CAD, heart failure, LVH, AF, biomarkers,
                ST segment, age risk, prevention, diabetes, emergency triage
      buildVocabulary(docs) — creates word→index mapping
      computeTFIDF(docs, vocab) — builds document-term matrix
      stopWords — filtered common words (the, is, at, etc.)
      medicalSearch(query) — finds best matching document
        → Tokenizes query → removes stop words → computes cosine similarity
        → Returns: {title, text, score}

    CLINICAL RECOMMENDATIONS:
      generateRecommendations(params) — threshold-based rule engine
        → Returns array of urgency-ordered recommendation strings

  Relationship to server.py:
    algorithms.js is the CLIENT-SIDE twin of server.py's AI logic.
    They both implement the same algorithms independently:
    - server.py = Python version (uses real XGBoost model)
    - algorithms.js = JavaScript version (pure logic, no model)
    The KB and A* in algorithms.js are used by the Clinical KB tab (search).
    The ML prediction ALWAYS comes from server.py (never from algorithms.js).

11. model.js                                                   [8.7 KB]
    THE FALLBACK — JavaScript ML Model Simulation
================================================================================

  What it is:
    A JavaScript class that SIMULATES the XGBoost model's behavior using
    hand-tuned weights. Used when the Flask server is not running.

  What it contains:
    class MLModel {
      featureWeights — calibrated importance values per feature:
        oldpeak:         0.22  (highest — ST depression is strongest predictor)
        exang:           0.18  (exercise angina)
        thal_reversible: 0.16  (reversible defect)
        thalch:         -0.15  (max HR — negative weight, higher is better)
        restecg_st:      0.14  (ECG abnormality)
        ...

      scaleFeatures(features)  — MinMax normalization (age/80, chol/300, etc.)
      predict(features)        — returns {probability, prediction, riskState}
      performSensitivityAnalysis(features) — runs 6 counterfactual probes
    }

    determineRisk(prob)  — returns "High/Medium/Low Risk"
    getRiskEmoji(risk)   — returns 🔴/🟡/🟢

  When it's used:
    Originally designed as a pure browser fallback. Currently, the app
    always talks to server.py for ML predictions. model.js provides the
    determineRisk() and getRiskEmoji() utility functions that app.js uses.

  Important distinction:
    model.js is NOT the real model. It approximates the XGBoost behavior
    using simplified linear weights. The REAL model is in:
      heart_disease_model.pkl → loaded by server.py
